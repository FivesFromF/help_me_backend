# Database Schema & Models

The backend uses **PostgreSQL** with the `pgvector` extension enabled for biometric facial embeddings.

---

## 🗄️ Core Tables

### 1. `citizens`
Stores citizen demographic information and emergency identifiers:
- `id` (UUID, Primary Key)
- `cognito_id` (String, Unique) — Linked to AWS Cognito identity
- `email` (String, Unique)
- `full_name`, `phone`, `avatar_url`, `date_of_birth`, `gender`, `address`
- `cccd_number` (Citizen ID, Unique)
- `face_embedding` (`vector(512)`) — Generated by AI service for facial search
- `emergency_contacts` (JSON)
- `is_verified`, `is_profile_updated`, `consent_regulation`

### 2. `medical_records`
Stores critical medical facts needed by first responders:
- `blood_type` (e.g. `O+`, `A-`)
- `allergies` (Text / Array)
- `chronic_diseases` (Text / Array)
- `medications` (Current prescriptions)
- `special_notes` (Organ donor status, pacemaker, implants)

### 3. `nfc_tags` & `qr_codes`
Emergency hardware tokens linked to citizens:
- `token_id` / `code`
- `citizen_id`
- `status` (`active`, `revoked`)

### 4. `emergency_reports` & `admins`
Incident management and administrative logs:
- `admins`: System administrators with full access
- `emergency_reports`: Timestamped triage incidents, location GPS coordinates, and situation descriptions.
